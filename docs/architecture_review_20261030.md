# KLQ整体架构检查与优化建议

日期：2026-10-30。生产源码基线：codex/python-runtime@8284847（最近安装主机0.13）。本轮只读审查生产代码，使用真实C+mock做最小复现、重链接已有对象生成调用图；没有访问设备/串口、烧录、下载用户程序或触发运动。以下建议尚未实施。

结论：当前“最小USB引导＋系统固件＋RAM用户程序＋协作解释器＋端口异步状态机＋后台快照”的方向适合现阶段固定积木。需要优先闭合通信事务、调度时间、新鲜度及故障策略；没有发现资源压力迫使整体重写的证据。

## 1. 优先级与证据

P1表示建议在继续扩大功能/形成发布基线前修正的可靠性问题；P2为随后安排的行为或恢复补强；P3为低风险整理。产品策略项不冒充代码违约。

| 编号/优先级 | 具体问题、触发与影响 | 建议 |
|---|---|---|
| A1/P1 明确缺陷 | USB RESET首次应答发送失败后，响应已缓存；同序号重试只重发OK，不执行尚未提交的复位。真实协议复现reset_calls仍0，新序号才为1。boot源码RUN也有相同结构。 | 将待执行动作纳入事务缓存；发送成功后仅提交一次，重试可完成未提交动作；已经执行的普通写操作不得重做。 |
| A2/P1 调度风险 | 普通USB回复每63B可同步等2秒；期间只处理电源键和升级模式外接口，普通电机/Python/语音/USB STOP不继续推进。256B解析预算不是时间预算。无IN读取时单包超时；间歇慢收时多包累计还可更长。 | 固定缓存＋非阻塞TX游标；主循环每次推进有限工作，停止/电机/电源先服务；日志有空才发或丢弃，不占关键路径。 |
| A3/P1 依赖新鲜度的缺陷 | 每个GET_SAMPLE回复均把sample_host_ms设为当前处理时刻。相同sequence/capture重复900ms仍被当age0；另一个复现中101ms进入IRQ环的回复到1000ms处理，也被当age0。距离条件可被旧数据误触发。 | 区分采集、接收、处理时间；仅新测量更新测量年龄；先判事务过期再发布数据，超龄积压回复丢弃。 |
| A4/P1 产品故障策略缺口 | motor_run后wait_distance遇传感器离线，或wait_tilt遇IMU失效，bool false和“条件未满足”相同。真实解释器/runtime模拟10秒仍RUNNING/error0，健康电机继续续发。当前API文档明确离线继续等，故不是代码违反已写契约，但需要产品决策。 | 等待结果拆为PENDING/TRUE/FAULT；区分正常无回波与掉线/数据过期，明确首次未接、短暂失联的宽限及故障停止策略。保留合法无延时循环，不把用户无等待循环当程序错误。 |
| A5/P2 条件性恢复策略 | main先执行用户程序、后轮询端口超时。模拟300ms停顿后，同目标不会绕过lease，已排除；但下一条不同方向命令能先授新lease，再继续ACTIVE而未报fault。 | 若要求超时后报错、显式重启，先服务驱动超时再推进脚本，或健康检查把lease过期视为不健康；先定义该安全恢复语义。 |
| A6/P2 明确缺陷 | 语音策略仅记最后seq，B0不清；传输层完整tuple去重已清。新peer同seq不同语义被误拒reason11；u8全局seq回绕也可能碰撞。 | 去除策略层冗余单seq去重，统一由完整tuple＋epoch判重；只在B0清状态仍不能解决无重启回绕。 |
| A7/P2 恢复缺口 | 主固件HardFault弱默认B .，无独立看门狗。固件本身异常后USB、按键、长按关机可能失效；时钟启动失败也停在循环。电机子板250ms是子板正常运行时的软件保护，其自身停顿同样不能当硬件失能保证。 | 先消除长阻塞，再加最小故障记录、基于主循环关键服务进度的看门狗；同步考虑引导/升级喂狗及电机从板故障失能，不在定时中断盲喂。 |
| A8/P2 性能问题 | 每次INFO重新逐位CRC整个APP。当前30952B对应247616次bit迭代；最大APP可3915776次，随固件增长拖慢调度。本轮未测CPU耗时，不换算成板上毫秒。 | 启动和固件END保留完整校验；INFO读缓存，BEGIN失效/END通过更新有效状态。 |
| A9/P2 时序说明问题 | 识别长按后等STOP最多150ms，但board_power_off先USB断连，固定再等300ms才拉低PC5；实际软件路径额外约300～450ms。 | 分离立即detach与重新枚举debounce等待；关机不必先等Windows；MOS/电池实际电气时序另测。 |
| A10/P2 运行上下文隐含状态 | 程序A设高档3结束后，程序B未设置功率会继承3；motor/move档位只冷启动默认2，RUN不重置。真实C已复现。 | 每次RUN建立明确默认上下文，或正式规定跨程序继承并要求生成器显式设置；避免上位机误以为默认中档。 |
| A11/P3 小缺陷 | 解析接受CR换行，错误行号仅数LF；pass\rklq.missing()\r第2行错误报第1行。 | 统一换行归一化或错误行计数。 |

## 3. 推荐优化顺序

### 第一批：消除跨模块时序问题

先修A1事务动作重试、A2有界收发和A3样本时间语义，再统一驱动超时与脚本推进顺序。建议关键服务每轮固定先处理取消/电源/驱动到期，再推进有限协议和VM工作；不在USB等待内部递归拼接更多业务轮询。确定A4/A5故障恢复策略后用同一规则覆盖Python、语音、诊断和升级。

验收应覆盖慢读/不读USB、同序号重传、RX积压、重复sequence、传感器掉线与不同目标恢复。测试先保留真实C最小复现，再接板；不要用diagnostic OPEN后的0证明正常停止，不把ACK当引脚或电机转速。

### 第二批：高收益小开销

- 相同显示去重：robot_ui.c:98–103每次直接整屏写。TM1640每屏19B，按代码delay推导下限约1.595ms，非实板测量。加13B最近帧/dirty可跳过重复画面；需要时再给动态图设置刷新上限，保持无延时循环合法。
- INFO移除全镜像CRC热路径；调试日志按需启用/有空发送；过期日志周期跳过，不追赶补发。
- 采样周期定义统一：SC7内部100Hz、待机读取10Hz、运行目标50Hz；CS100A响应后间隔40ms，IR20ms。加线时延后理论CS约22.5Hz、IR约39.1Hz，不能写成已保证25/50Hz。需要固定周期时按请求开始时间排下一次，并禁止错过周期后的突发追赶。
- 先测最差主循环耗时、STOP到ACK延迟、RX高水位、样本age和栈水位，再决定硬件I2C、DMA或定点数学。当前软件I2C/浮点不是已测的首要瓶颈，不直接为缩小代码删掉边界与恢复校验。

### 第三批：功能与可维护性闭环

- wait_ir仍明确返回不支持；双路IR应先确定左右通道/合并方式及0..100与设备0..1000刻度，再补条件等待。增加按实际实现返回的积木能力位，避免上位机可生成而主机必然报6。
- 当前解释器仅字面量参数、固定函数和循环，不支持变量、表达式、if、函数。现有26项范围可继续；若上位机要加入这些积木，先冻结语言/能力ABI，再比较小型预解析指令与扩展解释器。CRC下载成功不等于语法已通过，预检可分步加入，不把完整语言重写当第一步。
- UART5目前仅初始化，蓝牙传输未接。接入前设计每传输独立解析状态和单一下载/控制所有者，不能把USB/BLE字节喂进同一全局frame后混用缓存序号。
- 主机/传感器/音频Boot与APP版本要有整机manifest。C主控分支已提交，但共享F/main仍有最新UL/VOICE未提交输入和外部模型/SDK；不能承诺仅克隆本分支可重建当前整机。后续逐项审查合流，不覆盖共享脏工作树。
- 构建当前用glob加BOOT排除名单；可改明确源码白名单/feature配置，避免新系统模块漏进BOOT。属于构建治理，不为格式重排嵌入式代码。
- PA0电池采样、低电量策略、菜单尚未实现；阈值须依据电池/分压/供电路径确定。加实体恢复入口；目前APP损坏仍可由有效BOOT接USB恢复，但APP运行挂死时通常还要SWD或故障复位方案。

## 4. 资源与无需过早改变的部分

[极海APM32E103xCxE数据手册](https://global.geehy.com/uploads/tool/APM32E103xCxE%20datasheet%20V1.9.pdf)给出RET6为512KiB Flash/128KiB SRAM。0.13实际BIN30952B（30.23KiB），RO30884B，RW/ZI27632B（26.98KiB，含16KiB源码和2KiB栈），约用21.1%物理RAM。源码无malloc/calloc/realloc；startup声明的512B HEAP未被链接，不能再宣称删它可省512B。

已有对象重新链接生成静态调用图：660B + Unknown(Cycles, Untraceable Function Pointers)。默认异常死循环及函数指针使该数字不是完整IRQ叠加的最坏栈证明；2048B保留可先保留并加水位测量，不据此盲缩栈。证据build/architecture_review_20261030/audit.htm。

以下结构本身合理：

- 用户源码只在16KiB RAM，完成/停止/报错保留，下一BEGIN覆盖、MCU复位/断电清空；普通USB关闭不等于要清除完整程序。
- Flash的32KiB BOOT/478KiB APP/2KiB元数据边界和先失效、最后提交magic顺序可保留。当前单槽无自动回滚，但中断升级能留在BOOT重传，不需要为31KiB镜像马上搬分区。
- PC5在C运行库前保持电源；跳转关闭SysTick/清NVIC/设置VTOR和MSP已落实。
- 固定缓冲、有界循环、端口单未完成事务、子板失联停机和0x55只读反馈应保留。主机0.13已含EP RC_W0修复；驻留BOOT仍0.3，不能把应用升级当成引导已同步修复，后续单独核对与更新恢复链。

本轮不改变生产代码和当前设备。建议下一阶段先实施第一批，再做对应板测；其余功能按产品需求推进。详细机器证据architecture_review_20261030.json。
