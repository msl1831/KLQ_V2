# KLQ 精简 Python 与上位机积木接口 V0.1

状态：机器人端首版已实现；语音积木不在本版范围。

## 1. 上位机生成规则

用户程序是 UTF-8/ASCII 文本，通过现有 KLQ1 `BEGIN/DATA/END` 下载到 16 KiB RAM，断电或复位即丢失，不写 MCU 内部 Flash 或外部 Flash。程序入口是文件顶层，推荐首行固定生成：

```python
import klq
```

解释器只支持空行、`#` 注释、`import klq`、`from klq import *`、下表中的函数调用、`for _ in range(整数):`、`while True:` 和 `pass`。顶层不缩进，每级子积木固定增加 4 个空格。参数只能是数字字面量或自定义图案的十六进制字符串；不支持变量、表达式、函数定义、类、异常、列表或任意模块。该边界用于固定 RAM、Flash 和单次执行时间。

每次主循环最多推进一条语句。计时、传感器条件和无限循环均协作等待，USB `STOP`、端口通信和系统服务不会被用户程序占住。

## 4. 生成代码示例

```python
import klq
klq.display_face(1)
klq.move_power(2)
for _ in range(3):
    klq.move_for(0, 1.5)
    klq.wait(0.2)
klq.display_number(3)
```

在电机协议接入前，首个电机启动语句会以“不支持”结束程序，而不会假装电机已动作。

## 5. 运行错误

KLQ1 `INFO` 增加 `PY_ERROR` 和 `PY_LINE`。程序自然完成或被停止后 `USER_STATE=2`；运行错误也回到可再次运行的 READY 状态，并短暂显示错误图标。

| PY_ERROR | 含义 |
|---:|---|
| 0 | 无错误 |
| 1 | 语法或缩进错误 |
| 2 | 未知函数 |
| 3 | 参数格式/数量错误 |
| 4 | 参数越界 |
| 5 | 循环嵌套超过 8 层 |
| 6 | 底层设备或协议未支持 |
| 7 | 运行时状态错误 |

## 6. 底层接口

- `mini_python_poll()`：每轮推进一条语句或检查一个等待条件。
- `klq_runtime_*()`：用户 API 与板级驱动之间的固定边界。
- `external_port_status()`：读取后台发布的端口快照，不在 Python 调用中同步访问串口。
- `external_ports_set_active()`：用户程序运行时将 CS100A 轮询从 10 Hz 提升到 25 Hz。
- `klq_runtime_update_imu()`：主循环在程序运行时以 50 Hz 更新 SC7 快照，待机维持 10 Hz。
- `external_port_motor()`：电机协议接入点。当前返回不支持；取得真实电机 INFO、控制命令、功率范围和应答格式后在此实现。

程序停止、自然结束、运行错误或重新下载时都会调用 `klq_runtime_stop_all()`。电机设备端仍必须实现通信超时自动停机，才能覆盖线缆断开时主机停止帧无法送达的情况。
