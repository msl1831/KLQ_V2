# KLQ 精简 Python 与上位机积木接口 V0.1

当前：主机0.14，2026-10-30已安装。本轮增加传感器故障三态/250ms宽限、每次RUN恢复默认功率2、统一CR/CRLF/LF行号；普通积木函数名不变。正常使用无需连接USB，完整RAM程序自主运行；保护只针对程序实际调用的端口/内置设备和拥有的电机，允许无外设及多个同型设备。详见[0.14优化记录](optimization_014.md)。

验证历史：0.13的P2 motor_for正反、motor_run正反/motor_stop已有用户机械观察；低中档、其他口与双电机机械效果仍待验收，见[历史电机验收](verification_20261030_python_motor.md)。0.14本轮确认下载、无延时循环、CDC关闭/重开保留、STOP、半包取消，以及错误类型口调用后的退出/继续下载。用户另确认当前供电下物理拔USB仍显示12、短按STOP/RUN和重连正常；不把这些、历史机械结果或native故障注入说成0.14全功能实物复测。

26项接口的首轮模拟/实板边界分别保留在[2026-10-14矩阵](verification_20261014_blocks.md)与[0.9合流验证](verification_20261029_host_upgrade.md)。语音积木不在本版范围；红外普通采样已实现，wait_ir条件仍未接入。

本文只列上位机生成的语法和函数。内部轮询、调度与底层驱动由机器人负责；源码传输见[USB通信协议](host_usb_protocol_v0.1.md)。

## 1. 上位机生成规则

用户程序是 UTF-8/ASCII 文本，通过现有 KLQ1 `BEGIN/DATA/END` 下载到 16 KiB RAM，断电或复位即丢失，不写 MCU 内部 Flash 或外部 Flash。程序入口是文件顶层，推荐首行固定生成：

```python
import klq
```

解释器只支持空行、`#` 注释、`import klq`、`from klq import *`、下表中的函数调用、`for _ in range(整数):`、`while True:` 和 `pass`。顶层不缩进，每级子积木固定增加 4 个空格。参数只能是数字字面量或自定义图案的十六进制字符串；不支持变量、表达式、函数定义、类、异常、列表或任意模块。该边界用于固定 RAM、Flash 和单次执行时间。

每次主循环最多推进一条语句；计时、传感器条件和无限循环协作等待。0.14先处理端口到期事务/电机租约，再推进用户代码；USB应答异步发送，不要求用户在循环中插入延时来维持系统服务。每次RUN将单电机和移动功率恢复为2，只清本次执行上下文，不清后台缓存或按键状态。

RAM 程序在同一次上电期间完成、报错或被 `STOP` 后仍保持有效，可短按 PC4 或发送 `RUN` 再次运行。关闭电脑串口或USB会话重置不会停止完整程序，也不清完整源码；运行中仍继续自主执行。新一次 `BEGIN` 立即停止旧程序并覆盖同一缓冲区；若CRC错误，或设备在半包期间观察到CDC关闭/USB会话重置，半包取消，旧程序不会恢复，需重新完整下载。MCU复位或断电清空RAM；若拔USB导致实际失电，同样不能保留。

不带 `wait` 的 `while True` 或有限循环是合法代码。解释器按主循环协作执行，并限制单次调用中的内部跳转次数；PC4 短按、USB `STOP`、`BEGIN` 和电源键长按仍能处理。`try/except` 语法不在当前子集内；由固件统一捕获语法、参数、设备和运行时错误，停止用户程序并报告 `PY_ERROR`/`PY_LINE`，不要求上位机生成 `try`。

工作表中的“播报预设语句”和“等待听到语音指令”按本轮要求排除，未加入解释器。

`klq.wait_distance()`只检查指定端口；新测量快照年龄不超过80ms且状态1（有效）时，按严格小于/大于比较，不含等于。状态2/3/4（太近/超范围/无回波）是正常新测量，继续等条件；不把无回波本身判成程序错误。重复sequence/capture不刷新年龄。

距离口离线、类型不符、没有样本、年龄超过80ms，或状态0/5/未知，进入FAULT；持续250ms仍未恢复时退出为PY_ERROR7并请求所有电机停止。`klq.wait_tilt()`只检查内置IMU，使用100ms有效龄及同样250ms连续故障宽限；有效但未倾斜继续等待。恢复正常数据会清除本次连续故障计时。`klq.wait_button()`可以无限等待，不加这一超时。PC4短按或USB STOP仍可退出任意合法等待。

无需预先接满三个口：纯显示/按键程序不要求传感器在线，P1距离等待不检查P2/P3，多个相同传感器/电机不构成重复错误。电机运行只监测当前程序拥有的口；被使用资源故障时统一停止程序并请求全停，未使用口故障不误报。

## 4. 生成代码示例

```python
import klq
klq.display_face(1)
klq.move_power(2)
for _ in range(3):
    klq.move_for(0, 1.5)
    klq.wait(0.2)
klq.display_number(3)
```

当前驱动会校验所选端口设备身份；非电机口或不兼容设备会报不支持。上例需要端口1和2各接电机，当前单P2接线不能验收该双电机示例。每次RUN默认单电机/移动功率均为2；本次设置只影响后续启动/设置，motor_for从命令入队计时。驱动在租约过期时先故障停止，不接受靠换目标续期；显式停止后可重新运行。最近执行行用于异步错误定位。

## 5. 运行错误

KLQ1 `INFO` 增加 `PY_ERROR` 和 `PY_LINE`。程序自然完成或被停止后 `USER_STATE=2`；运行错误也回到可再次运行的 READY 状态，并短暂显示错误图标。

| PY_ERROR | 含义 |
|---:|---|
| 0 | 无错误 |
| 1 | 语法或缩进错误 |
| 2 | 未知函数 |
| 3 | 参数格式/数量错误 |
| 4 | 参数越界 |
| 5 | 循环嵌套超过 8 层 |
| 6 | 底层设备或协议未支持 |
| 7 | 被使用设备失效或运行时状态错误 |

PY_LINE从1开始；CR、CRLF和LF换行的同一源码位置报告相同行号。PY_ERROR7包括本程序拥有电机的异步故障，以及被调用传感器连续FAULT达250ms；不会因未调用的空口报错。完整源码在错误后仍可再次RUN，功率重新从默认2开始。
