# 1.5 秒电源键、双眼显示与通信回归（2026-09-23）

板卡为 APM32E103RET6。测试时没有电池，机器人 USB 与 DAPLink 同时连接；DAPLink 供电绕过 PC5 控制的 MOS。用户说明仅接机器人 USB 且没有电池时，充电芯片可能不提供稳定供电。以下长按结果是此供电条件下的软件关机/唤醒验证，不等同于电池供电下的真正断电冷启动验证。

## 实板动作

- 待机图案为无嘴巴的两只眼睛，每隔约 5～9 秒左右看和眨眼；用户观察确认显示正确。
- 运行中的 107 B RAM 示例程序交替显示数字 12 与开心表情。用户长按 PC4 后点阵熄灭、程序停止，机器人 CDC 端口从电脑消失；关机态短按 0.2～0.5 秒保持熄灭，再长按约 1.5～2 秒播放开机动画并回双眼待机。重新连接后 `USER_STATE=0, USER_VALID=0, UI=1`，RAM 程序已清空。
- 在 USB 引导下载箭头界面，用户长按 PC4 后箭头熄灭、CDC 端口消失；再次长按返回系统固件开机动画和双眼待机。
- 拔掉两条线后只接机器人 USB，点阵保持熄灭，随后长按仍未点亮；这一路无电池供电条件异常，不能据此判定冷启动门槛失效。重新接入 DAPLink 后设备可恢复；DAPLink 供电绕过 PC5。电池供电下的短按不开机、长按开机以及 PC5 电平时序待有电池后实测。

## 通信与运行

- `tools/test_protocol.py --port COM123`：26 组 ECHO、重复请求重放、CRC 错误、长度越界与错误后恢复通过。
- `tools/test_python_runtime.py`：语法/循环/等待/错误行号、未支持设备报错、无设备时的协作等待、USB STOP 以及主机不读取日志时自然结束均通过。
- `tools/test_user_program.py`：RAM 下载、整包 CRC、显示状态、RUN/STOP/FINISH、复位清空 RAM 程序通过。
- 在系统固件 0.6 上仅发送 107 B 示例程序的 `BEGIN` 和前 32 B `DATA`，确认 `USER_STATE=1, USER_RECEIVED=32, UI=2` 后，只拔插机器人 USB，DAPLink 持续供电。重新连接读取 `USER_STATE=0, USER_VALID=0, USER_RECEIVED=0, UI=1, USB_RESETS=4`；半包取消、下载箭头消失并回双眼待机。
- 最终引导镜像上的 `tools/test_update.py`：中断下载不能启动残缺镜像、整包 CRC 错误被拒绝，重新下载后系统固件运行、ECHO 及 `RESET` 返回引导通过。测试后已从引导执行 `RUN`，恢复系统固件。

本轮没有外接电机或红外设备。相关 Python API 仍明确报不支持；`external_port_motor()` 当前不发送控制帧，因此实际电机停机能力还需设备协议和实物联调。蓝牙用户程序下载及音频协议也不在已验证范围内。USB 协议在本轮测试范围内未发现回归。
