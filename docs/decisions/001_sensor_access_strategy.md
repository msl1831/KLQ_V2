# 传感器数据访问策略

状态：已确定

日期：2026-09-15

## 背景

当前主机每 100 ms 读取一次 SC7A20HTR，并以相同周期向在线 CS100A 发送 `GET_SAMPLE`，业务层取数约 10 Hz。SC7A20HTR 内部输出数据率为 100 Hz；CS100A 自身连续测量，测量速度随回波或 70 ms 超时变化。10 Hz 足够当前联调，但用户程序运行时若在每次 API 调用中同步操作 I²C 或串口，会产生以下问题：

- UART 一次无载荷请求和样本响应共 52 个字节，115200、8N1 的线时延约 4.5 ms，还需叠加设备处理时间。
- 设备失联时，单次 40 ms 超时及重试可能把一次 Python 调用拖长到百毫秒量级。
- 用户程序频繁读取会改变底层事务节奏，并可能延迟停止、电源、通信和其他端口服务。
- 三个外接端口必须各自保持“一次一个未完成请求”，不能由 Python 调用绕过事务状态机。

## 决策

采用**后台采集、静态快照、用户 API 读取缓存**的结构。普通 Python 传感器 API 不直接发起硬件事务。

每个传感器实例使用固定大小的静态快照，至少保存数值、设备状态、样本序号、采集时间、主机更新时间和通信错误。后台服务独立于用户程序推进，写入完整快照后再原子发布；用户 API 读取一致副本，不使用堆分配。

用户 API 分为两种语义：

1. 普通读取立即返回最新有效快照，并可查询 `sequence`、`age_ms` 和 `status`。目标是底层缓存读取不超过 1 ms，不等待串口或 I²C。
2. 需要新样本时使用“等待下一帧”接口。它按样本序号等待变化，必须设置超时并让出解释器执行权；它仍不绕过后台服务直接操作总线。

当数据超过设备定义的新鲜度阈值、设备离线或样本状态无效时，API 返回明确的传感器状态／错误，不无限返回旧值。停止、长按关机和电机安全处理的调度优先级高于传感器采集。

## 初始运行参数

Python 解释器接入后的首版实现采用以下参数：

| 数据源 | 待机／调试 | 用户程序活跃读取 | 初始新鲜度上限 |
| --- | ---: | ---: | ---: |
| SC7A20HTR | 10 Hz | 50 Hz | 25 ms |
| CS100A `GET_SAMPLE` | 10 Hz | 25 Hz | 50 ms |
| 后续串口传感器 | 由驱动静态表定义 | 由设备能力和协议定义 | 不超过三个采集周期 |

首版在任意用户程序运行期间统一提升后台频率，程序停止后降回待机频率，以减少解释器内的访问追踪状态。后续如果实测 CPU 或串口占用需要优化，再改为“首次读取后升频、连续 1 秒无读取后降频”；Python API 和快照语义不变。频率、超时和新鲜度均使用设备驱动的静态常量，不由用户脚本直接设置。UI 和 USB 调试日志保持 10 Hz，不得反向限制后台采集。

## 实现验收

- 普通缓存读取不产生 UART/I²C 发送，不等待外设响应。
- 三个串口端口仍各自最多一个未完成事务，sequence、CRC、超时重试和拔插重发现保持有效。
- 高频后台采集期间，用户停止、长按关机、USB／蓝牙协议处理和电机停止不被传感器超时阻塞。
- 使用主机时间和样本序号分别测量后台更新率、数据年龄、API 调用耗时和丢帧；不能用页面刷新率或 USB 日志行数代替采集率。
- 检查系统固件 map，确认新增缓存和调度状态为固定容量，Flash、RAM 和 CPU 开销在目标板上可接受。

首轮实测后可调整 50 Hz／25 Hz 数值，但“后台采集、缓存读取、有界等待下一帧”的接口语义保持不变。若某种设备协议只能按需触发测量，由对应驱动在后台事务层实现触发和完成，不把同步总线操作暴露给 Python。
