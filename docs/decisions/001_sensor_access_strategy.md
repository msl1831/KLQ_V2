# 传感器数据访问策略

状态：已确定，0.14实现规则已更新

初始决策日期：2026-09-15；本次更新：2026-10-30。当前实现与验证范围见[0.14优化记录](../optimization_014.md)及[机器人架构](../architecture_current.md)。

## 背景与不变原则

正常使用通常不接USB，观测页面只是调试出口；后台采集不能受页面刷新、日志输出或电脑是否读数限制。若每次Python调用同步操作I²C/UART，传输、超时和重试会占住解释器，并拖慢停止、电源和其他端口服务。115200/8N1下52字节UART往返仅线时延约4.5ms，还不含从板处理，不能直接当作API成本或实际帧率。

继续采用**后台采集、静态快照、用户API读缓存**，不把同步总线事务暴露给Python。每口最多一个未完成事务，固定缓冲、无堆；主循环先处理端口期限和电机租约，再推进VM。快照由主循环完整更新后供同一主循环读取，不把半帧数据发布给用户逻辑。

## 实例与保护范围

每个外接端口是独立实例，身份、测量、事务和错误均归属该口。允许没有任何外接设备，也允许多个同型传感器/电机；不得因为空口或同型重复而全局拒绝程序。

- 纯显示、计时和用户按键程序不要求外接传感器或IMU在线。
- wait_distance(P1)只检查P1的身份、状态和新鲜度，P2/P3不参与该条件保护。
- wait_tilt只检查内置IMU；wait_button可以无限等待，不套用传感器失效超时。
- 电机健康检查只针对当前程序拥有的口。已使用资源故障导致程序退出后，统一请求全停，以免同一程序其他电机继续运行。

## 0.14采集调度与新鲜度

| 数据源 | 待机目标周期 | Python运行目标周期 | 当前条件有效年龄 |
|---|---:|---:|---:|
| SC7A20HTR主机读取 | 100ms | 20ms | 100ms |
| CS100A GET_SAMPLE | 100ms | 40ms | 80ms |
| 双路IR GET_SAMPLE | 20ms | 20ms | 普通采样已接入；wait_ir条件尚未实现 |

SC7内部ODR仍为100Hz，不能把主机读取频率当作芯片产生新测量的频率。三个口的串行请求周期从请求开始起算，响应耗时占该周期；过期后最多启动一次，不补发积压周期。100/40/20ms分别对应10/25/50Hz调度目标，不保证有效新测量达到该帧率；实际受采集、响应、超时重试和主循环影响。

首版继续在任意用户程序RUNNING期间提高后台频率，停止后回待机；这不扩大设备保护范围。后续如果占用实测需要，再考虑首次读取升频/闲置降频，接口语义不变。频率和阈值为驱动静态常量，不由脚本任意改变。

0.14用显式sample_valid标记是否发布过测量，允许首样本sequence、capture_time_ms、主机时刻均为0。后续仅当sequence和capture_time_ms均相对上一份发布值变化时，才发布整份新测量并更新sample_host_ms。重复样本只续通信存活，不刷新样本年龄，不以“刚收到一帧”冒充“刚采到一次”。

年龄是主机接受新测量后的发布时间差；从板采集时钟与主机并未同步，不能将它当作已精确测得的端到端物理采集延迟。超时必须先于RX解析处理，积压旧回复不得在期限以后恢复旧事务或发布数据；重试换新传输序号，防止迟到包冒充本次响应。

## 条件等待与故障宽限

当前Python公开接口是wait_distance、wait_tilt和wait_button；尚未公开返回任意数值、age_ms或等待下一帧的完整通用接口。后续增加这些接口时仍读后台快照，不绕过事务层；普通读取应立即返回值与明确状态，需要新样本的等待必须协作让出并有超时。本轮不据此增加变量语法或wait_ir功能。

距离/倾斜条件使用三态：

| 状态 | 含义 | 行为 |
|---|---|---|
| PENDING | 新鲜有效，但条件未达到；距离新状态2/3/4为太近/超范围/无回波 | 正常继续等，无条件总超时 |
| TRUE | 新鲜有效且满足比较/倾斜阈值 | 执行下一条语句 |
| FAULT | 被调用设备离线、类型不符、无样本、年龄超限；距离状态0/5/未知，或IMU读取失效 | 从首次观察FAULT起连续250ms仍未恢复则PY_ERROR7、退出并stop_all |

距离比较只使用状态1，严格小于/大于，不含等于；倾斜阈值仍为15°。恢复正常测量会清除连续故障计时，无回波新测量不会被判为死循环或程序错误。250ms是故障观察宽限，不是从实际物理故障到电机停转的保证上界；还受有效龄、调度、通信和机械响应影响。

旧初始决策的25ms/50ms新鲜度没有作为当前参数继续沿用；本版明确采用100ms/80ms，与代码和Python文档一致。新阈值若需收紧，应先做实际采集率与年龄分布测量，再同步修改驱动、API和回归。

## 验证与后续

0.14的真实C回归覆盖：首0样本、重复sequence/capture不变龄、超时积压回复、40/20/100ms请求调度、80/100ms年龄边界、连续FAULT249/250ms、短暂恢复、无回波持续等待、按键无限等待，以及未调用口/同型多设备不误报。无延时循环合法且可由STOP或按键结束。

本轮实板确认RAM程序跨软件CDC关闭/重开继续运行、完整源码保留与半包取消；用户另确认当前供电下物理拔USB仍显示12、短按STOP/RUN及重连正常。错误类型口调用也能退出并继续下载，但这些不等于传感器拔线、电机断线或实际Fault的物理注入验收。0.13单P2电机的历史动作记录保留，其他口、双电机及长期稳定性仍独立验收。

后续以主机发布时间/新样本计数分别测后台更新率、有效新测量率、数据年龄、超时和API耗时，不用页面刷新率或日志行数替代；检查map和实际栈/CPU占用。停止、长按关机及电机故障处理优先于采集；不把软件失联停机或看门狗恢复宣传为电气硬停。
