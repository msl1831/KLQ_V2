# KLQ 外接端口与 CS100A 连机验证

日期：2026-09-15

## 验证对象

- 主机：APM32E103RET6，机器人 USB `COM123`，系统固件链接地址 `0x08008000`。
- 传感器：PY32F002BF15U6TR + CS100A，使用既有 UL 应用固件和 `UL/docs/klq_sensor_protocol.md` V1 协议。
- 主机系统固件：14868 字节，SHA-256 `8a2e16fe456dda77c6b922508cf8938a693f13624770e37f9fc7284bdc928b26`。
- 引导镜像未改变，仍为 9272 字节。本次只经主机 COM123 更新 APM32 系统固件，没有构建、修改或烧录 UL 传感器固件，也没有发送 OTA 命令。

链接映射显示系统固件总 ROM 14868 字节、总 RW 26248 字节。外接端口服务自身使用 1116 字节 BSS，包含三个独立 128 字节 UART 接收环形缓冲和三个最大 148 字节帧解析缓冲。

## 事务参数

| 项目 | 当前值 |
| --- | ---: |
| 物理层 | 115200、8N1、3.3 V TTL |
| 空闲端口 INFO 周期 | 500 ms |
| CS100A GET_SAMPLE 周期 | 100 ms |
| 请求超时 | 40 ms |
| 超时重试 | 2 次，复用相同 sequence 和请求 |
| 解绑条件 | 一次事务三次均超时，或连续三个非法帧 |

## 实测结果

主机自动在物理端口 1（USART1：PA9 TX、PA10 RX）发现设备：

| 字段 | 结果 |
| --- | --- |
| device_class | 1（传感器） |
| sensor_type | 1（CS100A） |
| UID | `4150354A/38343111/0080185B` |
| sample_status | 1（有效） |
| 稳定轮询错误 | 新增 timeout 0、frame error 0、UART error 0 |

一次 5 秒连续验证中，主机 USB 日志观察到 GET_SAMPLE 数据的样本序号从 107131 增至 107464，距离 5600～5601 mm、`echo_ticks` 16471～16474，在线端口没有新增错误。随后将传感器 MCU 暂停 1 秒并复位，主机状态按 `ON → OFF → ON` 转换，重新发现的 UID 完全一致。人为掉线累计 timeout 为 6；恢复后再次稳定采样期间该计数不再增加，frame error 和 UART error 保持 0。复位后传感器样本序号重新开始并持续增加，后续观测距离在 2882～5600 mm 之间且状态均为有效；本次验证通信链路，不作为距离精度标定。

主机同时通过以下检查：

- COM123 INFO 返回 `KLQ ROBOT FW 0.2`、`VALID=1`、`UI=1`。
- 主机 USB ECHO 在外接端口持续轮询时原样返回。
- `tools/test_external_ports.py` 验证端口、类型、UID、样本序号增长及稳定期间错误计数。
- `tools/test_external_reconnect.py` 使用已知 PY32 DAPLink 只执行 halt/reset，不写 Flash，验证解绑和重发现。

## 当前边界

UART1～3 是等价的任意设备端口；本次传感器实际插在端口 1，端口 2、3 的空闲 INFO 探测和超时状态正常。当前只注册 CS100A 业务解码，其他设备收到合法 INFO 后可记录身份，但需要新增对应服务才能执行业务命令。传感器 OTA 引导命令未实现、未启用、未测试。
