# RCWL9610A GPIO 偶发 0 距离诊断（2026-10-29）

## 当前结论与已确认输入

本板芯片为 RCWL9610A，GPIO TRIG/ECHO；用户确认目标固定不动、各距离都可能在观测网页显示 0 mm，远处更频繁；反馈电阻 R6 丝印为 753（75 kΩ）。

用户已将正确的《RGB超声波测距芯片RCWL-9610A-V2.0.pdf》放入 UL。本文最终结论以此 A 版手册为准，替代分析过程中误用旧 9610 手册的 20 ms/70 ms/R6 量程推断。旧 PDF 已从 UL 移除，不能再将其作为本板依据。

已确认三项：固件计时竞态能直接产生 NO_ECHO/0，已用原始 C 驱动复现；网页确实把无回波占位 0 显示为 0 mm；当前触发调度未遵循 A 版标示的 50 ms 测量周期。不能据此断言现场每次 0 都由同一原因造成，也不能认定芯片或 75 kΩ 电阻损坏。

## 正确 A 版资料核对

已读取正确手册全部 10 页，并渲染检查第 3/4/5 页的电路、参数与时序图。

| 项目 | A 版手册 | 对当前 UL 的意义 |
| --- | --- | --- |
| TRIG | 第 5 页：高电平大于 10 us | 当前约 50 us 符合此条件 |
| GPIO 周期 | 第 4 页典型 50 ms；第 5 页时序图也标 50 ms、可定制 | 不能按回波一结束加 1 ms 就开始下一次，也不是旧版的 70 ms |
| ECHO 延迟 | 第 5 页未规定旧版的 20 ms 处理延迟 | 不再假定固定 20 ms 后才有 ECHO；早到边沿需纳入接收状态机 |
| R6 | 第 3 页参考图标 753，即 75 kΩ | 用户阻值与参考图一致，没有依据直接换成 183/223 |
| 量程调节 | 第 4 页明确由 R9 调节 | R9=472 通常 5～6 m、622 通常 3～5 m、392 通常 6～7 m；针对厂家探头，实板 R9 尚未知 |
| 范围 | 第 4 页平整墙面典型 6 m、最大 7 m，精度 ±2% | 不是旧 CS100A 的 8 m；不能保证任意物体到 7 m 都有回波 |
| 电源 | 2.8～5.5 V；第 3 页特别提醒 CH340 类供电纹波影响稳定性 | 已确认 3.3 V 在静态范围内，动态纹波未测；不应直接照搬 CH340 专用措施到主机供电 |
| 芯片引脚 | 第 2 页：6=TRIG、11=ECHO、8=Blind Zone oFF | 与旧 9610 引脚不同，实际 PCB 应按 A 版核对；当前多数样本有效，不支持把 TX/RX 全部接错当首因 |

手册参数表的 50 ms 为典型值，不应虚构为厂家给出的严格最小/最大保证。但时序图已明确按 50 ms 调度，现有代码仅保证回波结束后约 1 ms，缺少相邻 TRIG 开始时刻的周期限制。应先用 60 ms 周期作对照（约 16.7 次/秒），稳定后再争取 50 ms（约 20 次/秒），并核实具体芯片是否为定制周期。

正确手册仍未定义 GPIO 无回波/超量程时输出的具体脉冲宽度。不能把 CS100A 的 66 ms 特征直接当作 RCWL9610A 保证。按 340 m/s，7 m 回波高电平约 41 ms；普通远距离传播本身不证明必须大幅增加 70 ms 等待，而增加超时也无法消除计时下溢。

用户提供的淘宝商品 https://item.taobao.com/item.htm?id=742113240494 （SKU 5823798454034）在网页工具中读取失败；RCWL 官网 https://www.sz-rcwl.com/index.php/index/show?catname=sa&id=71&lang=zh-cn 可确认产品名，但没有读到完整时序。最终参数取自用户后续提供的本地正确 A 版原厂手册，不使用其它模块或旧系列数据替代。

## 已复现的固件计时/状态竞态

源码位置：UL/firmware/app/Src/main.c:46～51；UL/firmware/app/Src/cs100a.c:49～64、68～92。

主循环先取 now_ms，处理 UART 后才调用 cs100a_poll。期间 TIM14/TIM1 IRQ 会更新 state 和 state_started_ms。如果主循环旧时间是 100 ms，而 IRQ 写入状态开始时间 101 ms，(uint32_t)(100-101) 变为 0xFFFFFFFF，即被当成超过 70 ms；WAIT_RISE 分支立即 publish(0, NO_ECHO, now_ms)。

相同差值用于 GUARD，也能让回波刚结束就提前重触发。另外 state 和时间戳不是一致快照，IRQ 在主循环判断期间完成测量后，主循环仍可能按旧状态发布超时。所以不应只在 main 多取一次时间；修复需一致获取时间/状态，并在提交超时或启动动作时保证状态未变化，临界区保持短而有界。

使用当前未修改的 cs100a.c、真实 cs100a.h/board.h 与最小 GPIO/时钟/IRQ 桩，在 UL/tests/build/rcwl_diagnosis 用 VC98 编译执行，输出：

~~~text
CONTROL: normal WAIT_RISE timeout at 70 ms
REPRO: IRQ timestamp=101, old poll=100, elapsed=0 ms -> status=4 distance=0
REPRO: 20 ms delayed valid ECHO, next TRIG at 22 ms, not 70 ms
REPRO: old poll timestamp skips 1 ms GUARD after IRQ sample publish
~~~

其中“20 ms 输入、22 ms 再触发”是隔离测试人为设置的信号，不是 A 版实测，也不证明 A 版有 20 ms 固定延迟；它证明现有调度不保证任何 50/70 ms 周期。其它两条则分别证明即时假超时和 GUARD 提前触发，均不依赖超声芯片型号。

其它需核实的风险：TRIG 高电平期间 ECHO 上升会被丢弃，因 WAIT_RISE 到 TIM14 结束才设置；A 版未承诺 20 ms 延迟，应预先准备捕获并实测波形。切换捕获极性后清 CC1 也有窄窗口丢边沿可能。500 kHz 的 16 位计数约 131 ms，正常数米脉宽低于此值，正确使用无符号差值不因普通计数回绕变成 0。

## 网页 0 的含义及现场证据

板端显式 0 主要来自初始化 NONE、WAIT_RISE 的 NO_ECHO，或极短脉冲导致换算为 0 并标 TOO_CLOSE。高电平超时当前上报 33000 ticks/11220 mm、状态 OUT_OF_RANGE，并不直接写 0；该阈值仍是旧 CS100A 约定，应另行按 A 版实测整理。

主控 external_ports.c 原样解码 distance/ticks/status；主控 0.9 的 tools/status_dashboard.py:250 对在线 UL 无条件显示 distance，没有把 sample_status=4 显示为“无回波”，所以无效占位 0 被呈现为 0 mm。Python 距离条件另有 VALID、在线和样本年龄检查，不能把网页现象等同于 Python 将无回波当作零距离比较。

本轮只读 http://127.0.0.1:8765/api/state，不另开串口。25 s 窗口取得 P1 的 30 条不同日志快照（不是全部声学样本）：28 条 ST=1、2 条 ST=4。两次 0 的 ticks 均为 0、设备保持在线，序号为 47668/47880。主机 TO/FE/UE 从头到尾为 4600/5/61，没有增长；有效距离约 186 mm。期间有 3 次 HTTP 读取超时，属网页读取层，不能当作 UART 错误，也不能把该窗口称作无丢失采集或把 2/30 当成传感器全部测量失败率。

主控工作树 docs/verification_20261029_sensors_live.md 另有同 UID 的 57 条日志中 5 条 D=0/ST=4 的记录。两次证据均说明观测到的 0 是驱动“未捕到有效回波”，而非真实测得 0 mm；尚不能区分每次是芯片实际无回波、触发被忽略、边沿漏捕或软件误判。

## 建议的处理顺序与剩余验证

1. 优先修复计时/状态竞态，以现有复现用例做回归，不能只增加超时。
2. 对 A 版加入相邻 TRIG 周期约束，先按 60 ms 对照，再验证 50 ms 稳定性；ECHO 未回低不得盲目再次触发，提前到达的 ECHO 也需正确捕获。
3. 网页按状态显示有效距离、无回波、超量程、无样本/离线。保留上次有效值时要显示过期标记和时间，不能悄悄把失败滤掉。
4. R6=753 与正确参考图一致，先保持；核实真正控制远距增益的 R9，并对 3.3 V 模拟电源纹波、探头和接收放大信号做必要测量。先用平整正对墙面分档记录，再评估远处弱回波/噪声影响，避免在软件问题未消除时先改硬件。
5. 修正后分别统计 VALID、NO_ECHO、OUT_OF_RANGE、原始 echo_ticks 和串口计数，比较近/远固定目标；远处更频繁可能叠加弱回波，不能用单一原因覆盖所有 0。
